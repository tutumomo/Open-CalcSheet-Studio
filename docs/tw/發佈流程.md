# 台灣版專屬發佈與簽名流程

依據 `docs/tw/工作計畫.md` §8.6，本文件說明 Open CalcSheet Studio 台灣版（`tutumomo/Open-CalcSheet-Studio`）之獨立發佈管線設計、軟體簽名評估與自動化安裝檔產出流程。

---

## 1. 上游與台灣版發佈管線之架構差異

| 項目 | 上游管線（`release.yml`） | 台灣版專屬管線（`release-tw.yml`） |
|---|---|---|
| **維護單位** | OpenAEC Foundation | 台灣版維護團隊（`tutumomo/Open-CalcSheet-Studio`） |
| **簽名金鑰** | 綁定 OpenAEC 官方金鑰指紋（`openaec-vingerafdruk.txt`） | 獨立發佈，不依賴上游私鑰；支援無憑證發佈（附 SHA256 校驗碼）或帶入台灣版自管憑證 |
| **預設語言** | `nl` / `en` | 強制檢核 `STANDAARD_TAAL = "zh-TW"`（繁體中文） |
| **計算模組** | 5 組 Eurocode + 荷蘭國家附錄模組 | 15 組台灣規範模組（RC／鋼構／基礎／水保／載重）＋5 組 Eurocode 模組（明確標註非台灣規範） |
| **前置驗證** | 跑上游檢查 | 跑全部 91 支 `check-*.mjs` 檢查 ＋ `valideer-tw-basis.mjs` 台灣基礎設施檢核 |

> **設計原則**：保留上游既有 `.github/workflows/release.yml`、`desktop-ondertekend.yml` 等檔案一字不變，確保 `scripts/check-uitlevering.mjs` 永遠通過，且未來合併上游（`git merge upstream/main`）零衝突；台灣版獨立使用 `.github/workflows/release-tw.yml`。

## 2. 獨立簽名策略評估（Code Signing Evaluation）

### 2.1 Windows（NSIS `*-setup.exe`）
- **現況評估**：`packages/desktop/src-tauri/tauri.conf.json` 僅啟用 `nsis` 打包（因版號 `2026.x.x` 主版號 > 255，MSI 格式不支援），且內嵌 `WebView2Loader.dll` 與靜默 Bootstrapper。
- **無憑證模式（預設）**：產出完整可安裝之 NSIS 安裝包，並於 Release 附上 `SHA256SUMS.txt` 供使用者核對雜湊值；Windows SmartScreen 首次執行時需點選「仍要執行」。
- **獨立簽名擴充**：若團隊取得 OV / EV Code Signing 憑證（或 Azure Trusted Signing），可於 GitHub Repository Secrets 設定憑證後，透過 `scripts/release/windows-ondertekenen.ps1` 在打包階段簽署。

### 2.2 macOS（`.dmg`）
- **無憑證模式（預設）**：產出 `.dmg` 映像檔並附 SHA256 校驗碼；macOS Gatekeeper 首次開啟可以 `xattr -cr "/Applications/Open CalcSheet Studio.app"` 或右鍵開啟。
- **獨立簽名擴充**：設定 Apple Developer ID Application 憑證與 App-Specific Password Secrets 後，即可啟用 `macos-notariseren.sh` 執行公證（Notarization）。

### 2.3 Linux（`.deb`）
- 產出標準 Debian/Ubuntu `.deb` 安裝包，附 SHA256 校驗碼，無需額外商業憑證。

## 3. 預設 `zh-TW` 配置保證

台灣版安裝檔啟動時預設即為繁體中文介面與台灣結構計算書架構，由以下機制共同確保：
1. **`packages/desktop/src/i18n/config.ts`**：
   - `export const STANDAARD_TAAL = "zh-TW";`
   - `i18next.init({ lng: STANDAARD_TAAL, fallbackLng: "zh-TW", ... })`
2. **結構計算書預設架構（`packages/desktop/src/rapport/model.ts`）**：
   - 當語言為 `zh-TW` 時，新報告預設 `opzetSoort = "tw"`（依台灣結構計算書慣例：1 設計概要 → 2 設計規範 → 3 材料強度 → 4 載重 → 5 結構分析 → 6 構材檢核）。
3. **發佈管線自動守門**：
   - `release-tw.yml` 的 `verify` 階段在編譯前自動檢核 `STANDAARD_TAAL === "zh-TW"`，若遭意外改動立即中斷發佈。

---

## 4. 觸發台灣版自動發佈步驟

1. 確認所有測試在本地與 CI 皆通過：
   ```bash
   npm run check
   node scripts/valideer-tw-basis.mjs
   ```
2. 前往 GitHub Repository → **Actions** → 選擇 **Release (Taiwan Edition / 台灣版發佈)**。
3. 點選 **Run workflow**，填入：
   - `tag`：例如 `v2026.45.2-tw.1`（須符合 `^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z._-]+)?$` 格式）。
   - `draft`：`true`（建議先建立草稿，檢視產出之 `.exe` / `.dmg` / `.deb` 與 `SHA256SUMS.txt` 無誤後再於 GitHub 介面正式發佈）。
