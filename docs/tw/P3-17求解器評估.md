規格 `docs/OCSS_TW_開發需求規格.md` 的 P3 寫的是「之後再做（先開 issue 評估，不要硬做）」。
這份文件就是那個評估。

## 現況（專案已經有的東西）

| 能力 | 位置 | 現在怎麼用 | 能不能經 API 拿到 |
|---|---|---|---|
| 連續梁 1–4 支點 | `packages/core/src/ligger.ts`（`liggerOplossing`、`liggerReacties`、`liggerOmhullende`、`liggerExtremen`） | 模組的計算語言函式（`ligger…`），設計時算 | 只能透過模組自己的計算表間接取得 |
| 平面剛架＋α_cr | `packages/core/src/raamwerk.ts`（`raamwerkOplossing`、`raamwerkReacties`、`raamwerkVerplaatsingen`、`raamwerkSamenvatting`） | 同上，`tw-*` 模組的穩定檢核會用 | 同上 |
| 板模型（Open FEM Studio） | `packages/desktop/src-tauri/fem-brug`、`rekenen/femStudio.ts`、`@fem` 區塊 | 計算書裡宣告 `@fem`，按「檢核」或列印時送 FEM Studio | **不行**：`sheet_evaluate` 只給 `{type:"fem", name, status, check:"unchecked"}` |
| 斷面檢核（`@toets`） | `packages/core/src/toetsBlok.ts`、`rekenen/toetsCache.ts`、Rust `fem_studio.rs` | 同上 | **部分**：只給 `uc`、`status`、`check`，`uitkomst.toetsen[]`、`versie`、`datum` 沒出去 |

也就是說：**求解器不是沒有，而是沒有 API 介面**。`@toets` 的答案物件裡已經有
`uc_max`、`status`、`voldoet`、`toetsen[]`（含每根鋼筋／每支構材的 `uc_max` 與 `maatgevend`）、
FEM Studio 版本與日期；`@fem` 也有 `gevallen`、`model`（節點／元素／網格數）、各組合的極值。
缺的只是把它們放進工具回應。

## 三個選項

### A. 把既有結果放進 API（小，建議先做）

`sheet_evaluate`／`calc_evaluate` 的 `toets` 與 `fem` 行補上完整答案：

- `toets`：`clause`（若有）、`version`、`date`、`items[]`（`id`、`uc_max`、`status`、`maatgevend`），
  並保留現有的 `uc`／`check` 不動（只增不改）。
- `fem`：`model`（節點、元素、網格、彈簧、厚度）、`cases[]`（名稱、總載重、總反力）、
  各組合的極值摘要；`modelSvg` 另以 `sheet_read` 的既有格式提供較合適（4 MB 上限）。
- `check` 仍一律 `unchecked`，除非有明確的容許值可比較——不因為「算出來」就標成合格。

成本：半天。風險低（只新增欄位）。好處：下游不必自己 parse 計算書文字就能拿到檢核結果，
這正是規格 P1-7「結構化結果」的自然延伸。

### B. 開一個求解器工具（中）

新工具 `frame_solve`（或 `beam_solve`），把 `raamwerk.ts`／`ligger.ts` 包成有穩定 schema 的 API：
節點、構材（E、A、I）、支承、載重 → 反力、端彎矩、位移、`α_cr`。

成本：1–2 天（schema 定案、單位慣例、與 FEM Studio 的結果對照測試）。
風險：與 Open FEM Studio 的結果不一致時，使用者會問「哪個對」；必須在回應裡寫明
「这是本 App 內建的一階／二階梁柱解法，板與複雜幾何請用 Open FEM Studio」。
好處：小模型不必等 FEM Studio，且可離線。

### C. 新寫通用求解器（大，不建議）

任意構架、釋放、移動載重、影響線。這與 Open FEM Studio 功能重疊，會出現兩套引擎
對同一模型的答案不同，且維護成本高。除非下游有明確需求（例如必須在無 FEM Studio 的
環境算板），否則不做。

## 建議

1. **先做 A**：純新增欄位，對現有工具零破壞，馬上讓 `@toets`／`@fem` 的結果可機讀。
2. **B 視下游需要**：若 `ocss_crosscheck.py` 或設計引擎需要「不經計算書」直接算梁／剛架，
   再做 B；先以 `raamwerk.ts` 的既有測試數值當黃金檔。
3. **C 不做**：板與複雜幾何交給 Open FEM Studio。

## 驗收條件草案（給 A）

- `sheet_evaluate` 回應中，含 `@toets` 的表的 `toets` 行有 `version`、`date`、`items[]`；
  沒有答案時不出現這些欄位，`check` 仍為 `unchecked`。
- 含 `@fem` 的表的 `fem` 行有 `model` 與 `cases[]`；未檢核時只有 `status`。
- 舊欄位（`uc`、`status`、`check`、`type`、`name`）一個都不變；`docs/api.md` 與 `docs/mcp.md` 同步。
- 新的 `scripts/check-mcp.mjs` 段落以假的 toets/fem 答案覆蓋「有答案／沒答案」兩條路徑。
