# 上游同步流程

本文件說明如何把上游 `OpenAEC-Foundation/Open-CalcSheet-Studio` 的新功能合併進台灣版
`tutumomo/Open-CalcSheet-Studio`，以及合併後如何重新驗證與發佈。

台灣版的改動以「新增檔案」為主（`tw-*.ts`、`check-tw-*.mjs`、`docs/tw/`），與上游重疊的只有少數幾行，
所以正常合併的衝突面很小。安裝識別（`productName`／`identifier`）已與上游不同，合併不會把它改回去，
上游新版也不會覆蓋已安裝的台灣版；原因見 [`發佈流程.md`](發佈流程.md) §5。

---

## 0. 一次性的設定

```bash
git remote -v
# origin    https://github.com/tutumomo/Open-CalcSheet-Studio
# upstream  https://github.com/OpenAEC-Foundation/Open-CalcSheet-Studio.git

# 沒有 upstream 才需要：
git remote add upstream https://github.com/OpenAEC-Foundation/Open-CalcSheet-Studio.git

# 讓 Git 記住解過的衝突，下次同類衝突自動套用
git config rerere.enabled true
```

> **不要用 GitHub 網頁的「Sync fork」按鈕。** 有衝突時它會提供「Discard N commits」，
> 按下去會直接丟掉台灣版的提交。一律用下面的指令同步。

---

## 1. 同步前先留退路

```bash
git switch main
git pull origin main            # 先確定本機 main 與 fork 一致
git tag pre-sync-$(date +%Y-%m-%d)
git push origin pre-sync-$(date +%Y-%m-%d)
```

出問題時可以一行回到同步前：

```bash
git reset --hard pre-sync-YYYY-MM-DD
```

---

## 2. 看上游有什麼、先預覽衝突

```bash
git fetch upstream
git log --oneline HEAD..upstream/main        # 尚未合併的上游提交
git diff --stat HEAD...upstream/main         # 動到哪些檔案
```

想先知道會不會衝突，可以不動工作區預覽（Git 2.38 以上）：

```bash
git merge-tree --write-tree HEAD upstream/main
```

輸出結尾若有 `CONFLICT`，就是需要手動解的地方。

---

## 3. 合併

```bash
git merge upstream/main
```

若出現衝突，用 `git status` 看清單，逐檔解完後：

```bash
git add <檔案>
git merge --continue
```

### 衝突處理原則

| 檔案 | 上游通常改什麼 | 保留方式 |
|---|---|---|
| `packages/desktop/src-tauri/tauri.conf.json` | `version` 版號 | 保留上游的 `version`；`productName`、`identifier`、視窗 `title`、檔案關聯名稱保留台灣版 |
| `src/i18n/locales/*/common.json`、`settings.json`、`backstage.json` | 新增或調整詞條 | 上游的新詞條照收；`appName` 維持 `Open CalcSheet Studio TW` |
| `src/templates/index.ts` | 新增模組註冊 | 兩邊的註冊都留 |
| `src/components/calc/projectTree.ts` | 新增目錄項目 | 兩邊都留，台灣模組放在 `cat-tw-*` 分類下 |
| `README.md`、`README.nl.md` | 檢查腳本數量、功能說明 | 兩邊內容都留；數量以 `node scripts/check-readme.mjs` 算出的為準 |
| `docs/CHANGELOG.md` | 新條目加在「Nog niet uitgebracht」 | 兩邊條目都留 |
| `AGENTS.md`、`CLAUDE.md` | 規則調整 | 以台灣版為準（見 `CLAUDE.md` 的合併說明） |

若上游動到 `productName` 或 `identifier`（很少見），**一律保留台灣版的值**，否則又會回到被覆蓋的情況。

---

## 4. 合併後一定要驗證

```bash
npm ci                    # 上游可能改了依賴
npm run check             # 94 支以上，全部要綠
cd packages/desktop && npx tsc --noEmit -p . && cd ../..
```

常見的非衝突失敗：

- **`check-schermtekst.mjs` 紅**：上游新增了介面詞條，`zh-TW` 還沒補。到
  `src/i18n/locales/zh-TW/` 對應的命名空間補齊同一個鍵即可（鍵要相同，值可以是繁中）。
- **`check-readme.mjs` 紅**：`scripts/check-*.mjs` 數量變了，更新 `README.md` 與 `README.nl.md` 的數字。
- **`check-versie.mjs` 紅**：版號沒同步，依腳本提示更新。
- **`check-renders.mjs` 紅**：新的上游樣板在 `templates/` 這一層出錯，照訊息修正。

全部通過後再提交合併結果（合併本身已是一個 commit，這一步通常不需要額外提交）：

```bash
git push origin main
```

---

## 5. 重新發佈台灣版

版號跟著上游走，標籤加上 `-tw.N`：

- 上游 `2026.46.0` → 台灣版第一個標籤 `v2026.46.0-tw.1`
- 同一版號再修 → `v2026.46.0-tw.2`

在 fork 的 Actions 頁面手動觸發 **Release (Taiwan Edition / 台灣版發佈)**，或用指令：

```bash
gh workflow run release-tw.yml \
  --repo tutumomo/Open-CalcSheet-Studio \
  --ref main \
  -f tag=v2026.46.0-tw.1 \
  -f draft=false
```

`gh` 預設可能解析到 upstream，所以 `--repo` 一定要寫。流程會重跑全部檢查，再跨平台打包並建立 Release。

---

## 6. 另一台電腦

另一台電腦同步前，先確認它自己的改動已 commit 並推到具名分支（不要停在 detached HEAD），
再 `git pull origin main`；否則它的改動會與合併結果分岔。

---

## 7. 絕對不要做的事

- `git reset --hard upstream/main`：會把台灣版的提交全部丟掉。
- `git push --force`：會覆蓋遠端歷史。
- 衝突時整份選「接受上游」：會把台灣版的改動洗掉。
- GitHub 網頁的「Sync fork」在有衝突時按「Discard」。
